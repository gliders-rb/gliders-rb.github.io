Protobuf

Preview

field_struct-protobuf sits at 1.0.0.pre1. Its spec settles the behaviour, though no release has gone out yet.

field_struct-protobuf gives a struct a Protocol Buffers form without a protoc run. It prints .proto source for other teams, registers a message class with google-protobuf, and converts instances to messages, to binary and back.

You choose the field numbers. Each field carries proto: {number: n} and the gem never guesses one. If it numbered by declaration order, moving two lines around in a class would quietly change the wire format.

The schema of a struct

Section titled “The schema of a struct”

FieldStruct::Protobuf.proto prints the file for a single class. It prints from the descriptor that gets registered, so the text and the registered message can’t drift apart.

Here is the whole file for Fleet::Trip:

The module Fleet turns into the package. Each class gets its own file with one message in it. A file imports the files of whatever structs it refers to. A struct can refer to itself, but two structs can’t point at each other.

Type mapping

Section titled “Type mapping”
FieldStruct type Protobuf
:binary bytes
:string, :immutable_string, :uuid, :email, :url, :symbol string
:big_decimal, :decimal string, so 19.9 stays exact
:date string, as 2026-11-01
:boolean bool
:integer int64
:float double
:time, :datetime .google.protobuf.Timestamp; the zone: offset is restored on decode
:value .google.protobuf.Value; numbers come back as Floats
a struct class its message
:array, of: X repeated X

Singular scalars are all optional, so presence is explicit: a field nobody set reads back as nil, not 0 or an empty string. Arrays differ. Empty and unset look the same on the wire, so an unset array reads back as [].

Take a trip that starts at the north depot and carries a battery reading.

Code that protoc generates from the printed .proto can read these bytes. The adapter’s own specs prove it by compiling the text with protoc, so this page relies on that claim and does not run it.

Use case: messages

Section titled “Use case: messages”

message_class builds the message for a class one time and registers it in google-protobuf’s generated pool. to_message and from_message convert a single instance.

Message field names are the serialize :protobuf names, as given. Pass serialization: when you want the names of another format.

Unset stays unset

Section titled “Unset stays unset”

It raises rather than guess

Section titled “It raises rather than guess”

When there is no exact mapping, the call raises ArgumentError and names the class and field. Cases are a field with no number, a number used twice, a union, an array of arrays and a custom type.

Module functions

Section titled “Module functions”
Call Returns
proto(klass) the .proto text
file_name(klass), full_name(klass), package(klass), message_name(klass) the names given to the file and message
file_descriptor(klass) the registered descriptor
message_class(klass) the google-protobuf message class
to_message(struct), from_message(klass, message) one instance, to a message and back
encode(struct), decode(klass, bytes) binary

Limits

Section titled “Limits”
  • Output is proto3 only. There is no oneof, enum, map, service or option.
  • Registration lasts for the process and cannot be undone. If a class gains a field after its message was built, nothing notices, and the stale message rejects the new field. Reloading code means restarting.
  • Each class registers under one serialization:. Asking for a second one raises.
  • For malformed bytes, decode lets Google::Protobuf::ParseError pass through.
  • An integer past 64 bits raises RangeError.
  • format: and in: are not checked here. The struct does that.
